# stock-tv — 桌面小电视(ESP32-C3)A股/指数实时行情屏显
## ✨项目亮点
1. ESP32‑C3驱动TFT屏幕，支持静态图片、轮动壁纸渲染
2. **设备直连公开数据接口**，免 PC、免服务器、免常开主机；配网、切模式、改自选股全部在网页上完成
3. **Web网页控制器**，浏览器完成设备全部配置，支持网页背景自定义、快捷WIFI配置、一键重置
4. A股/指数多标的轮播，分时图、日K图解析渲染，支持自定义别名
5. 根据时钟，可选自动亮度调节或手动锁定亮度，按时段自动调节亮度
6. **天气城市自定义**：内附 2428 条城市代码记录，支持拼音名称自定义，10个常用城市快捷切换
7. **SPIFFS自动清理**：启动时自动删除无用文件，保持存储空间宽松，存储监控一目了然
8. **取数与阻塞优化**：把"一轮 loop 内多次取数"改为硬性互斥（一轮最多 1 次），配合分时/日K 的分级刷新周期（分时 120 秒、日K 30 分钟）。在 ESP32-C3 + 手机热点环境下单机实测，阻塞占空比由 ~45% 降至 ~25%，控制台首页加载由 5.2 秒降至 2.3 秒 —— **属特定测试条件下的观测值，会随网络环境波动，非通用指标**

## 🧾硬件BOM清单
- 主控：ESP32‑C3（QFN32，160MHz，320KB RAM，**4MB Flash**，WiFi+BLE）
- 屏幕：**ST7789 / ST7789P3** 驱动，**1.54″ 240×240** SPI 接口 TFT 彩屏（12P 接口，如金逸晨 GMT154-07）
- 供电：Type‑C USB供电（5V）

> **不需要**树莓派、PC 或任何常开主机 —— 一块 ESP32‑C3 + 一个 USB 充电头即可独立运行。

## 第零步:确定硬件引脚(可参考ESP32‑C3公开电路图,具体以本仓库表格与platformio.ini 为准)

| 信号 | GPIO | 备注 |
|---|---|---|
| SCL | 3 | SPI时钟 |
| SDA | 5 | SPI MOSI |
| DC | 2 | |
| RST | 6 | |
| BL | 1 | AO3401 P-MOS,**低电平点亮** |
| CS | — | 屏端接地,固定选中 |
| USB | 18/19 | 原生USB,Type-C直刷 |

> ⚠️ **别把屏幕模块的丝印引脚号当成 GPIO 号** —— 这是本项目踩过的坑：
> 模块上标着 `4`/`5` 的焊盘，接的是芯片的 `IO5`/`IO6`。按丝印填 `SDA=4`/`RST=5` 会得到
> **"背光亮但纯黑"**（数据到不了屏）。表中是**已验证通电可用**的 GPIO 号。
> 本仓库 `TFT_eSPI_Setup.h`、`firmware/` 均已按此表配好，无需自行换算。
> （**要改引脚的话**：这份配置在仓库里存了 3 处、内容相同，得一起改 —— 见「疑难排查」里的「📍 显示配置在哪」。）

## 第一步:编译烧录主工程

**`arduino/integrated/` 是完整全功能主工程，推荐用 Arduino IDE 编译烧录。**

### 1) 开发板支持包（core）

开发板管理器装 **esp32 (Espressif)**，选 **ESP32C3 Dev Module**，并设置：

| 项 | 值 |
|---|---|
| 分区方案 | **No OTA (2MB APP / 2MB SPIFFS)** |
| USB CDC On Boot | **Enabled** |

> ⚠️ **core 请用 2.x**。主程序背光调光用的是 `ledcSetup()` / `ledcAttachPin()` / `ledcWrite(channel, duty)`
> 这套 **2.x 专有 API**；core 3.x 改成了 `ledcAttach(pin,freq,res)` / `ledcWrite(pin,duty)`，会编译失败。
> 注：**core 是"开发板支持包"，在开发板管理器里找，不在库管理器里。**
>
> 💡 **本仓库已内置对较新 2.x core 的兼容修正**（在 `TFT_eSPI_Setup.h` 里，见该文件开头的说明）。
> 不装这个修正的话，用较新的 core（如 2.0.17）会**烧进去就启动崩溃、反复重启**
> —— 原因是 TFT_eSPI 2.5.43 与新版 ESP-IDF 的一个 SPI 宏冲突。
> 按上面第 3 步把 `TFT_eSPI_Setup.h` 覆盖过去，即已包含该修正，**无需额外操作**。
> （实测：core 2.0.4 与 2.0.17 均可编译；2.0.4 下这份修正对构建结果零影响。）

### 2) 库依赖

用库管理器装上（下列版本为实测可编译版本，供复现参考）：

| 库 | 实测版本 | 用途 |
|---|---|---|
| **TFT_eSPI** | 2.5.43 | 屏幕驱动（引脚配置见下） |
| **WiFiManager** | 2.0.17 | AP 配网门户 |
| **ArduinoJson** | 6.21.5（6.x / 7.x 均可） | 解析分时/日K JSON |
| **TJpg_Decoder** | 0.0.3 | JPEG 壁纸/相册解码 |

### 3) TFT_eSPI 引脚配置

把根目录的 `TFT_eSPI_Setup.h` 覆盖到库目录下的 `User_Setup.h`
（引脚、驱动、SPI 模式都在里面，已按「第零步」的表格配好，**无需自行换算**）。

### 4) 上传

上传后设备进入配网模式（见第二步）。

⚠️ **无需修改任何代码**：WiFi 账号密码在设备的配网页面上填，自选股、城市、亮度等全部在网页控制台上改。

## 第二步:配网与网页控制台

设备首次上电（或重置后）会开一个热点 **`SDD小电视`**：

1. 手机/电脑连该热点 → 打开 `192.168.4.1`
2. 填写你家 WiFi 的账号密码 → 保存
3. 设备重启后连上你的 WiFi，用串口日志里的 `WebServer: http://<IP>` 地址即可打开控制台

**控制台能做的事：**

| 分组 | 能改什么 |
|---|---|
| 模式切换 | 时钟 / 天气 / 相册 / 股票 四模式一键切换 |
| 壁纸 | 静态壁纸选择、动态壁纸（壁纸轮播）、关闭壁纸 |
| 股票视图 | 分时图 / 日K图 |
| 股票配置 | 自选股代码、显示别名（最多 4 只） |
| 屏幕亮度 | 手动 0–100%，或开启按时段自动调节 |
| 天气城市 | 2428 条城市代码搜索、常用城市一键切换 |
| 刷新间隔 | 行情刷新周期（见下） |
| SPIFFS | 存储占用查看、文件列表 |
| WiFi 管理 | 更换 WiFi / 重置 WiFi（进 AP 配网模式） |

### 🆕 网页快捷指令（可直接在地址栏用）

| 路由 | 作用 |
|---|---|
| `/set?refresh=N` | **设置行情刷新间隔（取值 5~600 秒）**。<br>N 秒的含义是：**每 N/4 秒轮询一只标的**，单只标的名义周期约 N 秒；若该轮已被分时/日K 取数占用，这一次会跳过，实际间隔会更长。<br>默认 60 秒。调小会更实时，但会增加设备网络负担与耗电 |
| `/set?mode=N` | 切换模式（0=时钟 1=天气 2=相册 3=股票） |
| `/set?brightness=N` | 设置亮度（0–100） |
| `/status` | **只读** JSON：固件版本、IP、运行时长、剩余堆、最大连续块、RSSI、当前模式等 |

> 💡 **三类数据各有独立的刷新闸门**（取数节流的设计结果）——
> 但它们**共用**"一轮 loop 最多只能取一次数"的互斥，所以并非彼此无关：
>
> | 数据 | 周期 | 说明 |
> |---|---|---|
> | 行情（现价/涨跌幅） | 由 `/set?refresh=N` 决定，默认 60 秒 | 一轮轮询一只标的 |
> | 分时图 | **约 120 秒** | 把上游的**逐分钟**数据均匀抽样成 **48 个点**显示 ⇒ 每点约代表 5 分钟（**开盘头 48 分钟例外**，那时几乎逐分钟）。刷新再快，多数时候拉回的也是同一张图 |
> | 日K线 | **约 30 分钟** | 日K**当天那根盘中一直在变** ⇒ 30 分钟是"响应速度 vs 取数开销"的取舍，理由是"变化慢"，不是"不会变" |
>
> ⚠️ **互斥**：若某一轮已被分时/日K 占用，行情那一次会**跳过**（该标的等到下一轮），
> 所以实际间隔可能略长于标称值。

> ⚠️ **`/status` 仅用于人工排障，请勿轮询。** 每一次请求都会占用设备时间；
> 高频轮询（例如 1 秒 1 次）会显著拖慢设备、影响屏幕刷新。
> 需要长期监控请用串口日志，不要在它上面跑定时任务。

## 疑难排查

### 🆘 先做这两件事（屏不亮 / 烧完启动就崩）

这两步互不依赖，但都围绕**同一套显示配置**（它为什么存了好几份、又为什么不合并，见下一节），请按顺序用：

| 顺序 | 怎么做 | 能得到什么结论 |
|---|---|---|
| **① 先判屏和接线是否正常** | **两条路，择一：**<br>· **用 Arduino IDE 的（最省事）**：**先做完「第一步」第 3 步**（把 `TFT_eSPI_Setup.h` 覆盖到库目录），再打开 [`test_display/test_display.ino`](test_display/test_display.ino) 编译烧录 —— 屏上会红→绿→蓝→白轮播<br>· **想连字体一起验**：烧 `firmware/` 调试工程（PlatformIO 工程；怎么编译烧录见 [`firmware/README.md`](firmware/README.md)） | 能出颜色 / 出字 ⇒ **屏、背光、接线、以及这份显示配置都是好的**，问题在配置或程序侧<br>**仍然黑屏** ⇒ **还不能断定是硬件坏了**，按顺序查：① 供电与接线（回「第零步」核引脚）② 库目录里的 `User_Setup.h` 到底是哪一份 ③ 串口启动日志有没有报错 |
| **② 把主工程配置拉回已知可用** | 确认根目录 `TFT_eSPI_Setup.h` 已**覆盖**到库目录的 `User_Setup.h`，再重新编译烧录 | **覆盖后就正常** ⇒ 之前是漏了这一步（该文件内带 core 兼容修正，漏了会"烧完启动即崩"）<br>**仍不行** ⇒ 看下面的对照表 |

> ⚠️ `test_display` 的**局限（务必知道）**：它**只测纯色、不显示文字**。
> 它能证明"屏和接线是好的"，但**测不出"字体定义漏了"这个坑** ——
> 那个坑的表现是"有颜色、一个字都没有"。要连字体一起验，用 `firmware/`。
> 另外它**自己不带显示配置**（用库目录里那份），所以**必须先做完第 3 步**再烧；
> 否则可能因为库里的旧配置而黑屏，让你误判成硬件坏了。

> 💡 这两个自检程序**都不联网、不写 NVS、不碰 SPIFFS**
> （`firmware/` 实测：跑过前后 NVS 分区逐字节相同）。
> **前提是照常规方式烧录** —— 分区方案保持「No OTA…」不变、且**不勾选 "Erase All Flash"**；
> 满足这个前提，拿它们排障**不会弄丢你已配好的 WiFi 和已上传的图片**，用完直接烧回主工程即可。
> （若换了分区方案或整片擦除，NVS/SPIFFS 就可能被清掉 —— 那已经不是"排障"了。）

### 📍 显示配置在哪（共 3 处，内容相同，改一处要同步改其余）

| 用在哪 | 位置 | 当前状态 |
|---|---|---|
| **主工程**（Arduino IDE） | 根目录 `TFT_eSPI_Setup.h` → 覆盖到库目录 `User_Setup.h` | ✅ **日常只需管这一处** |
| **调试工程**（PlatformIO） | `firmware/platformio.ini` 里 `build_flags` 的 `-D` 那一串 | ✅ 当前生效 |
| 上一条的副本 | `firmware/include/User_Setup.h` | ⚪️ 当前**不生效**（因为定义了 `USER_SETUP_LOADED`，TFT_eSPI 会跳过它），留作兜底 |

> **为什么不做成一份？** 试过，**没成** —— TFT_eSPI 2.5.43 本身支持"随 sketch 再放一份配置"
> （`tft_setup.h`），本来可以把这几处并成一处；但那样编出来的固件**编译能过、宏也逐项核对无误，
> 烧进真机却在启动时崩溃**（根因未查明）。所以最终**保持各存一份，没有合并** ——
> 这是**刻意**的，不是遗漏；**当前保留已验证方案，合并方案的启动异常尚未定位**（完整记录见 `firmware/platformio.ini` 末尾）。
> 改引脚时记得 3 处都改；日常使用完全碰不到后两处。
> **真要动手改**（引脚/字体/大改固件）→ 操作细节在 [`firmware/README.md`](firmware/README.md)，
> 含 PlatformIO 使用、只写 app 区不碰 NVS 的烧法、以及出事了怎么备份还原。

### 常见现象对照表（按命中率排序）

> 📌 下表里的 `-Dxxx=1` 是 **PlatformIO / 编译参数**写法。
> **用 Arduino IDE 的话，请改成在库目录的 `User_Setup.h` 里写 `#define xxx`**（去掉 `-D` 和 `=1`）。
> 这几个都是**编译期**开关 —— 改完必须重新编译烧录，网页上改不了。

| 现象 | 处理 |
|---|---|
| **烧录后启动即崩、串口反复刷 `Guru Meditation Error`（`Store access fault`）** | 较新的 Arduino core 与 TFT_eSPI 2.5.43 的 SPI 宏冲突（详见下方说明）。<br>① 确认第 3 步已把本仓库的 `TFT_eSPI_Setup.h` 覆盖到 `User_Setup.h` —— **该文件内置了修正**；<br>② 仍不行就把 core 换成 **2.0.4** |
| 花屏/无显示 | 确认 `TFT_eSPI_Setup.h` 已覆盖库里的 `User_Setup.h`；再试 `-DTFT_SPI_MODE=SPI_MODE3`(CS接地批次差异) |
| **颜色反相**（整屏像底片/负片） | 这是 **INVON/INVOFF** 的问题：增删 `#define TFT_INVERSION_ON`（PlatformIO 写 `-DTFT_INVERSION_ON=1`） |
| **红蓝互换**（R↔B 通道颠倒） | 这是 **MADCTL 颜色顺序位**的问题，**与"颜色反相"是两回事**，**不要**用 `tft.invertDisplay()`（它只做整屏反相）。正确做法是加 `#define TFT_RGB_ORDER 1`（1=RGB；去掉或写非 1 即 BGR） |
| **画面偏移约 80 行** | 加 `#define CGRAM_OFFSET`（PlatformIO 写 `-DCGRAM_OFFSET=1`）。<br>⚠️ **它会连带把颜色顺序切成 BGR**（同一条 MADCTL 位）—— 所以开完这条若发现红蓝对调了，**正是这个原因**，用上面那条 `TFT_RGB_ORDER` 调回来即可 |
| 显示方向不对 | `integrated.ino` 里 `tft.setRotation(0)` 改 0-3 |
| **行情不更新 / 显示 `--`** | ① 设备是否已连上 WiFi（看串口 `WebServer: http://...`）<br>② 路由器能否访问外网<br>③ 股票代码格式是否正确（见下方"符号规则"） |
| **网页能开但很久才出来** | 正常现象：这台设备上一次网络往返本身就要 1 秒以上（开 `CMP_BUILD 1` 可见 `[T]` 日志）。<br>**不要在页面没出来时反复点击** —— 会触发浏览器的连接取消，反而更容易报错 |
| **点快了偶尔弹"拒绝了我们的连接请求"** | **已知限制**：设备是单线程处理 HTTP 请求，上一次响应还没发完时，新连接会被直接拒绝。<br>**触发条件**：连续快速点击、或在首页加载中途再次点击。<br>**恢复方法**：等 2~3 秒后刷新页面即可；控制台已加导航防抖，明显降低了触发概率 |
| **切换 WiFi / 换了路由器** | 控制台底部「⚠ WiFi 管理」→「更换 WiFi」；实在连不上就「重置 WiFi」进 AP 配网模式 |
| 烧录失败 | 按住BOOT(GPIO9接地)重新上电再烧;或用CH340G接UART焊盘救砖 |

### 🔧 要提交 Issue / 想自己排查？先打开诊断构建

主工程源码顶部有一个构建开关（**是源码里的一行，不是网页按钮** —— 改完要重新编译烧录）：

```c
#define CMP_BUILD 0    // 0 = 发布构建（默认，正常使用）  1 = 诊断构建
```

改成 `1` 重新烧录后，串口会多出两类信息：

| 输出 | 内容 |
|---|---|
| `[T] <类型> <代码> <ms>ms ok=<0\|1>` | **每一笔网络取数花了多久、成功与否** —— 定位"卡顿/响应慢"最直接 |
| `[HB] ...` | 每 60 秒一条：堆余量、最大连续块、RSSI、单轮最长耗时 |

**提 Issue 时把串口日志贴上来，基本能直接定位问题。** 两种构建**业务逻辑完全相同**，只差这些诊断输出。

> 💡 想长期观察内存是否稳定（比如怀疑有泄漏），用 `CMP_BUILD 1` 跑几小时，看 `[HB]` 里的
> `free` 和 `maxAlloc` 两列有没有持续下降即可。

## 符号规则

- 股票/指数:`sh600519` `sz000001` `sh000001`(上证指数)
💡注意：填写时确保股票代码长度无误，避免出错或乱码

> ⚠️ **本版不支持场外基金。** 主工程统一按腾讯股票行情接口解析，
> 而该接口对 `f005827` 这类场外基金代码不返回数据（实测返回"无匹配"）。
> 场外基金的处理只存在于**早期 PC daemon 版本**（`daemon/app.py`，配 `arduino/stocktv` 使用）——
> 它查的是东财**历史净值**接口（`api.fund.eastmoney.com/f10/lsjz`），
> 与主工程的行情链路不是同一条路，已不属于当前主工程的能力范围。

## 数据接口说明

### 由**设备**直接访问的第三方服务

| 服务 | 地址 | 协议 | 用途 |
|---|---|---|---|
| 腾讯财经行情 | `qt.gtimg.cn/q=` | HTTP | 实时行情（A股/指数） |
| 腾讯分时/日K | `web.ifzq.gtimg.cn/` | HTTPS | 分时走势、日K线 |
| 中国天气网 | `d1.weather.com.cn/weather_index/` | HTTP | 实时温度、湿度、气压、AQI（官方数据源，10 分钟刷新） |
| 阿里云 NTP | `ntp.aliyun.com` / `ntp6.aliyun.com` | NTP | **对时**（时钟、自动亮度、日K 判期都依赖系统时间） |

- 均为当前使用无需密钥访问的第三方接口
- 天气接口使用 9 位城市代码，本项目内附 **2428 条**城市代码记录（`assets/city_data.json`）
- **城市名显示限制**：屏幕最多显示 8 个英文字母（超出会被截断）
- ⚠️ 分时/日K 走 HTTPS，但使用 `setInsecure()` **跳过证书校验**（省 Flash/RAM），
  属于为资源受限设备做的取舍 —— 对"看行情"这类用途可接受，但请知悉它不防中间人。

### 由**浏览器**访问的第三方服务

打开网页控制台的「图片+JSON设置」页时，页面会从 **jsDelivr CDN** 加载图片裁剪组件
（`cropperjs`，用于相册上传前的 240×240 裁剪）。这是**你浏览器**发起的请求，设备本身不访问它。

⚠️ **该页三个上传入口对它的依赖不一样，别当成"都可以忽略"**：

| 入口 | 需要这个组件吗 |
|---|---|
| 网页壁纸（`m.jpg`） | **不需要** —— 直接选图上传（页面注明"无需裁剪"） |
| 城市数据（`city_data.json`） | **不需要** —— 直接选 JSON 上传 |
| **相册图片（`1/2/3.jpg`）** | **需要** —— 必须经裁剪组件才能上传，页面**没有**直传的备用入口 |

⇒ 若 CDN 不可达（离线、断网、被拦截），**相册就换不了图**；另两个入口仍然可用。

### 关于隐私

**当前实现未发现向项目作者服务器上传配置或图片的逻辑。**
设备配置（WiFi、自选股、城市）保存在设备自身 NVS，图片保存在设备自身 SPIFFS。

> ⚠️ 这**不等于**"完全离线"：如上表所列，设备和浏览器都会访问若干第三方公开服务；
> 控制台运行在普通 HTTP 上，**同一局域网内可见**（详见 [SECURITY.md](SECURITY.md)）。

**注意**：所有接口均为第三方公开服务，数据仅供展示学习，不构成任何投资或气象决策依据。
